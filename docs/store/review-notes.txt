Z8 review information — factual draft; attach only to the matching tested build

Z8 is a local Android terminal and Linux development environment. It provides project workspaces, multiple terminal sessions and a preview for local development servers. It does not provide its own user accounts, AI model service, model-request proxy, shared provider accounts or included AI usage.

Core access
No Z8 account is required. Start the app and unpack the included base environment using available device storage. This base preparation does not require downloading the development toolset. Create or open a project and launch a terminal. The shell, project navigation and local preview can be reviewed without signing into an AI provider. Verify the exact first-run button labels against the final candidate before submitting these instructions.

Suggested local workflow
1. Prepare the local development environment and open a demo project.
2. Run pwd and printf in its terminal. Open Settings > Project tools, select Python, review dependencies and the network choice, then install it to test Python or a local web server.
3. Open another terminal session and switch between the sessions.
4. Start a sample local web server inside the project and open its localhost address in Z8's preview.
5. Open Settings to inspect App language, Privacy policy, Data storage and deletion, Environment and external tools, and Open-source licenses and source.

Optional external clients
Users explicitly choose whether to install official CLI clients such as Codex and Claude Code and sign in directly with their own provider accounts. Authentication, service eligibility, subscriptions or charges are controlled by the external provider. Do not mark every feature as unrestricted merely because Z8 itself has no login. The final App access response must disclose any external account or payment requirement and supply a review path acceptable to Google. No reviewer credentials have been supplied in this draft.

Executable delivery
The application includes the Android host runtime, PRoot loader and a Linux filesystem. The base image is included. User-selected tool installation downloads additional distribution packages, Node.js, or official CLI binaries. Optional daily checks retrieve public version metadata for Codex, Claude Code and the Node.js 24 maintenance line at most once per 24 hours when Z8 is visible; they do not install code. Check now is an explicit one-time metadata request. These include native ARM64 code executed under PRoot using the Android kernel and app UID. PRoot is not a separate-kernel virtual machine or a security boundary between projects. The app does not download APK or DEX self-updates. Users and third-party tools can download or update additional Linux executables. This description does not assert that these flows qualify for a Google Play execution-policy exception.

Foreground services — rc8 draft; attach matching final-candidate demonstrations
Interactive terminals use TermuxService with specialUse while an actual interactive PTY is running or its requested shutdown is being verified. The user creates a terminal and starts work; commands and child processes continue when switching apps, with a dedicated terminal notification. Delay would make interactive command execution unusable, and interruption can terminate a running command or local server. Stopping terminal work ends its sessions; reopening does not silently replay commands.

Finite environment preparation, selected tool installation and confirmed whole-project deletion use the separate Z8PreparationService with dataSync. The user starts setup, creates a project that needs preparation, confirms an install/update, or confirms deletion of a selected project. Work consists of local extraction/copying/file processing or explicit package download, verification and setup. Progress and a Stop tasks action appear in a separate notification. Deferred work postpones the user's requested operation; interruption stops active and queued finite jobs and requires explicit retry. Android timeout and Stop tasks do not stop unrelated interactive terminals. The finite-work service stops when no jobs remain. Android's Active apps Stop ends the whole app, which is a separate control.

Deletion removes the selected project's source files, HOME and environment. Before file removal starts, cancellation keeps those files. After removal starts, Stop tasks may leave partial deletion; already deleted files cannot be restored. The app keeps the remaining project addressable for an explicit deletion retry. Demonstrate deletion only with a disposable test project, preserving another project's known files and terminal work. Do not describe interrupted deletion as universally preserving all files.

The service types are not enabled together for every operation: each service runs only for its own active work. If both an interactive terminal and preparation are active, both may have separate notifications. No boot-triggered service or scheduled background tool updater is used.
