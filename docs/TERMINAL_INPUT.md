# 터미널 입력과 알림 동작

2026-10-17 갱신. 터미널 에뮬레이터는 기존 Termux를 유지하며 `tools/patch-terminal-input.py`가 고정 upstream에 패치를 적용한다. 이번 갱신에는 앱·브라우저 복귀 시 입력 연결 갱신과 터치 선택 범위 확장을 포함한다.

## 입력 계약

| 입력 | 동작 |
| --- | --- |
| 터치 길게 누르기 | 단어 선택, 양 끝 핸들로 범위 조정, 선택 툴바의 복사·붙여넣기. 명시적으로 누른 툴바 동작은 즉시 선택을 닫음 |
| 마우스 왼쪽 드래그 | 일반 터미널에서 로컬 텍스트 선택. 화면 가장자리 이동 시 기록 이동 |
| TUI가 mouse reporting을 켠 상태 | 왼쪽 클릭·드래그를 프로그램에 전달 |
| Shift + 왼쪽 드래그 | mouse reporting 중에도 로컬 선택. 버튼을 누른 순간 경로를 고정하여 중간에 Shift를 놓아도 혼합되지 않음 |
| 마우스 휠 / 트랙패드 | 한 detent당 기본 3행. 작은 수직 이동은 누적해 정수 행만 반영. 프로그램 reporting 활성 시 보고, Shift를 누르면 로컬 기록 이동 |
| 오른쪽 클릭 | 터미널 메뉴 |
| 가운데 버튼 | 누른 시점에 한 번 붙여넣기. 누른 채 움직여도 반복하지 않음 |
| Cmd(Meta) + C / V | OS가 앱에 이벤트를 전달하는 경우 선택 복사 / 붙여넣기. 전달된 선택 없는 Cmd+C는 아무 글자·신호도 보내지 않음. 키를 누르고 있어도 반복 붙여넣기 없음 |
| Ctrl + Shift + C / V | 기본 복사 / 붙여넣기 단축키. 기존 Ctrl + Alt + V도 유지 |
| Ctrl + Shift + / | 키를 누르는 동안 단축키 패널 표시. / 또는 modifier를 놓거나 창 포커스를 잃으면 닫음 |
| Cmd(Meta) + H | OS가 앱에 이벤트를 전달하는 경우 같은 단축키 패널 표시. 시스템이 먼저 처리할 수 있으므로 기본 안내 키는 Ctrl+Shift+/ |
| Ctrl + C | Meta·Shift 없이 누르면 기존 터미널 interrupt 입력 유지 |
| 포인터 hover | 텍스트 I-beam |
| 다른 세션 선택 | 기존 선택 범위·핸들·툴바·대기 중 붙여넣기 확인창·지연된 터치/관성 스크롤 해제. 새 PTY에 이전 제스처를 적용하지 않음 |

줄바꿈이 든 앱 붙여넣기는 내용을 확인한 뒤 진행한다. 선택 툴바, 앱 메뉴, 마우스 가운데 버튼, 키보드 단축키가 같은 경로를 사용한다. IME가 **한 번에** 여러 줄을 commit하는 경우도 이 경로로 보낸다. IME Enter 한 글자는 기존 입력으로 유지한다. 키보드가 여러 별도 입력 이벤트로 분해한 붙여넣기를 앱이 확실히 구분할 수는 없다.

확인창은 원래 붙여넣기 대상 PTY와 에뮬레이터를 보관하며, 세션을 바꾸거나 대상이 종료되면 다른 세션에 내용을 넣지 않는다. 붙여넣기 실행 시 Termux의 제어문자 제거와 bracketed-paste 처리를 그대로 사용한다. 일반 Ctrl+C 및 CLI 권한·sandbox 정책은 변경하지 않는다. TUI로 보내던 마우스 드래그가 취소되면 release 이벤트를 마무리하여 프로그램에 버튼이 계속 눌린 상태를 남기지 않는다.

2026-10-31 추가: Android 자동완성(Autofill) 결과도 요청한 PTY에 연결한다. 세션 전환·앱 일시 중지·뷰 분리 시 요청을 취소하고, 늦게 도착한 값은 다른 세션에 기록하지 않는다. 정상 결과는 공통 붙여넣기 경로를 사용하므로 여러 줄이면 확인창이 표시된다. 이 경계와 제공자 취소 실패는 호스트 회귀 검사로 검증하며, 실제 비밀번호 관리자 앱과의 호환성 검증은 별도다.

## 워크스페이스 단축키

### 복귀와 선택 범위

앱 일시 중지·브라우저 진입 때 이전 IME 연결을 무효화한다. 실제 PTY와 입력 연결 세대가 일치하는 콜백만 문자·삭제·키 이벤트를 전달한다. 앱 복귀, 접기·펼치기, 기존 브라우저 탭 닫기, 프로젝트·세션 선택은 표시 중인 터미널의 크기와 입력 연결을 갱신한다. 포커스를 다른 입력란에서 빼앗거나 키보드를 강제로 띄우지 않는다.

복귀 자체는 사용자가 읽던 기록 위치를 보존한다. 실제 입력·붙여넣기 때 현재 프롬프트가 있는 화면으로 이동한다. 화면 밖에 있는 입력란에 글자가 들어가는 것처럼 보이지 않도록 하기 위한 동작이다.

터치 선택은 실제 글꼴 행 높이와 열 너비로 핸들을 계산한다. 가장자리에서 핸들을 유지하면 기록을 계속 스크롤하며 범위를 확장한다. 키보드 표시로 높이만 바뀔 때는 선택 범위를 이동해 보존한다. 열 수가 바뀌는 접기·펼치기에서는 텍스트가 재배치되므로 기존 범위를 해제한다.

세션을 길게 눌러 **최근 출력 복사**를 선택하면 해당 세션의 화면과 최근 기록 최대 1,000행을 네이티브 클립보드로 복사한다(최대 128K UTF-16 코드 단위). CLI 명령이나 AI 권한을 사용하지 않는다. 이는 Codex 내부 셸 명령이 샌드박스 오류로 실행되지 않는 문제와 별개다.

### 키 매핑

앱 화면의 키 처리는 `Z8WorkspaceKeys`가 담당한다. 단축키 안내 다음, 터미널·브라우저의 기본 키 처리 전에 실행한다. 프로젝트를 새로 만들거나 AI 도구를 자동 실행하는 단축키는 없다.

| 입력 | 동작 |
| --- | --- |
| Ctrl + Shift + T | 선택한 프로젝트에 새 터미널. 선택한 프로젝트가 없으면 프로젝트 목록을 엶 |
| Cmd(Meta) + T | OS가 앱에 전달하는 경우 같은 새 터미널 동작 |
| Ctrl + Tab | 현재 프로젝트의 다음 탭. 마지막에서 첫 번째로 순환 |
| Ctrl + Shift + Tab | 현재 프로젝트의 이전 탭. 첫 번째에서 마지막으로 순환 |
| Ctrl + Shift + B | 현재 프로젝트의 브라우저 탭 열기 또는 기존 탭 선택. 프로젝트 미선택 상태에서는 생성하지 않음 |
| Ctrl + L | 브라우저 탭에서 주소 입력란 선택 |
| Ctrl + R | 브라우저 탭에서 현재 미리보기 새로고침 |
| Esc | 브라우저 탭에서 연결된 원래 터미널로 복귀. 탭은 유지 |

탭 순환에는 해당 프로젝트의 터미널과 이미 열린 브라우저 탭이 포함된다. 예를 들어 `Terminal 1 → Terminal 2 → 브라우저 → Terminal 1`로 이동하며, 역방향은 `Terminal 1 → 브라우저 → Terminal 2`다. 순환 자체로 새 터미널이나 브라우저를 만들지 않는다. 다른 프로젝트의 세션으로 건너가지 않는다.

Ctrl+L/R와 Esc는 브라우저가 선택된 경우에만 가로챈다. 터미널의 화면 정리, 이력 검색, TUI Escape와 일반 Ctrl+C는 기존 경로를 유지한다. Alt를 포함한 조합과 Ctrl+Meta를 함께 누른 조합도 가로채지 않는다. Android 뒤로 가기는 브라우저에 이전 페이지가 있으면 먼저 페이지를 이동하고, 없으면 원래 터미널로 복귀한다. Esc는 페이지 이력과 관계없이 터미널로 복귀한다.

한 번 누른 단축키는 반복 DOWN이 들어와도 동작을 다시 실행하지 않는다. modifier를 먼저 놓더라도 그 키의 반복·해제까지 소비하여 터미널에 문자나 제어 신호가 새지 않게 한다. 상태는 키보드 장치별로 추적하고 앱 일시 중지·창 포커스 상실 때 초기화한다. 포커스 복귀 후 반복 이벤트만으로 새 터미널을 만들지 않는다.

CLI의 인증 요청은 요청을 보낸 정확한 프로젝트와 터미널을 기록한 뒤 z8 위에 브라우저 소유 Custom Tab을 연다. 지원하지 않는 브라우저는 일반 브라우저 화면으로 열릴 수 있다. 창을 닫으면 원래 대상이 남아 있는 경우 해당 터미널로 복귀하며, 새로운 세션을 생성하지 않는다. 프로젝트를 바꾸면 열린 브라우저 탭과 렌더러를 정리한다.

## 스크롤 처리

`SOURCE_MOUSE`와 `SOURCE_TOUCHPAD`의 `ACTION_SCROLL`을 처리한다. 소수점 수직 이동량을 장치·입력 경로별로 누적하므로, 작은 트랙패드 움직임마다 무조건 3행씩 튀지 않는다. 수직값이 0인 가로 제스처나 유효하지 않은 값은 세로 스크롤을 만들지 않는다. 한 이벤트의 작업량은 최대 120행으로 제한한다.

장치가 바뀌거나 로컬 기록·TUI mouse reporting·alternate buffer 사이의 전달 경로가 바뀌면 누적 잔여량을 초기화한다. 터미널 세션 전환과 터미널 뷰 분리 때도 초기화하여 이전 제스처의 잔여량을 새 대상에 넘기지 않는다.

로컬 기록 이동은 목표 행을 기록 범위 안으로 한 번 계산하고, 최종 viewport를 한 번 갱신한다. 여러 행을 이동할 때 매 행마다 선택 핸들과 화면을 갱신하던 작업을 줄인다. TUI mouse reporting과 alternate buffer에 전달해야 하는 행별 이벤트는 유지한다. 이 최적화는 입력 정책과 갱신 횟수 개선이며, 물리 트랙패드의 응답 속도나 배터리 절감 수치를 측정했다는 의미는 아니다.

## Cmd 키와 에뮬레이터 구분

기존 구현에는 로컬 마우스 선택과 Ctrl+Shift+C/V가 있었지만, Cmd 키를 나타내는 Android Meta 경로는 없었다. 이제 `onKeyShortcut`과 `onKeyDown`이 같은 복사·붙여넣기 처리기를 사용한다. 키보드 배열이나 한글 IME의 출력 문자 대신 물리 C/V 키 코드와 [Android `KeyEvent.isMetaPressed()`](https://developer.android.com/reference/android/view/KeyEvent#isMetaPressed())를 사용한다. 이 복사·붙여넣기 처리기는 Alt를 함께 누른 조합과 C/V 이외의 키를 가로채지 않는다. 별도의 워크스페이스 단축키는 위 표의 범위에서 처리한다.

Mac에서 AVD를 조작할 때는 macOS나 에뮬레이터가 Cmd 조합을 먼저 소비할 수 있다. 이 경우 앱에 Android Meta 이벤트가 도달하지 않는다. 에뮬레이터의 **Settings → General → Send keyboard shortcuts to**를 가상 기기로 설정하는 방법은 [공식 Emulator 안내](https://developer.android.com/studio/run/emulator-extended-controls)에 따른다. 합성 Meta 이벤트 성공, Mac 호스트의 실제 Cmd 전달, Android 기기에 연결한 USB/Bluetooth 키보드 전달은 각각 별도로 확인한다.

2026-10-05 API 37 AVD에서는 Android 입력 경로에 `SOURCE_KEYBOARD` Meta+C를 주입하자 z8 복사 대신 Google 계정 확인 화면(`Checking info` / `MinuteMaid`)으로 전환됐다. 시스템 단축키의 선행 소비와 일치하는 관측이며, 연락처·캘린더 중 어느 bookmark가 이 화면을 열었는지는 이 결과만으로 단정하지 않는다. 이 AVD의 Meta+C는 미지원으로 기록한다. 앱 콜백에 직접 전달한 호스트 테스트 성공과 구분한다.

AOSP [PhoneWindowManager](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/policy/PhoneWindowManager.java)는 앱 전달 전에 시스템 단축키를 처리하고 Meta 조합을 예약한다. [ModifierShortcutManager](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/policy/ModifierShortcutManager.java)는 Meta 조합에 대응하는 앱 실행 intent를 처리한다. 공개 [Activity.dispatchKeyShortcutEvent](https://developer.android.com/reference/android/app/Activity#dispatchKeyShortcutEvent(android.view.KeyEvent))는 앱에 전달된 이벤트를 처리하는 콜백이며 이 시스템 처리를 선점하지 않는다. 따라서 기본 사용법은 Ctrl+Shift+C/V와 터치 선택이고, Cmd 지원은 OS가 전달하는 범위로 제한한다. 설정의 **입력 → 단축키 보기**에서도 사용법을 열 수 있다.

단축키 hold 패널은 터미널 포커스를 가져가지 않는 비터치 PopupWindow다. 지원하는 조합의 H·/ 눌림과 반복·해제만 소비하고, 일반 Ctrl+C/H는 기존 터미널 입력으로 유지한다. modifier를 먼저 놓으면 패널을 닫되 남은 H·/ 반복과 해제는 계속 소비한다. Meta+H는 AOSP에서 홈 이동 단축키이므로 앱 전달을 보장하지 않는다. 창 포커스 상실과 앱 일시 중지 시 패널과 held-key 상태를 정리하며, 포커스 복귀 후 반복 키만으로 다시 열지 않는다.

## 세션 상태

프로젝트를 포함한 실행 요청은 항상 해당 프로젝트의 Linux 준비/실행 경로를 거친다. 앱 내부 intent에 guest 플래그가 빠져도 Android 기본 셸로 조용히 내려가지 않는다. Android 셸은 실행 진단에서만 명시적으로 사용할 수 있다.

AI·설치·인증처럼 목적이 있는 작업은 실제 프로세스가 끝나면 종료 상태와 출력을 유지하고, 사용자가 목록에서 제거한다. 실패 뒤 일반 셸을 이어 열어 AI가 실행 중인 것처럼 표시하지 않는다. 종료 탭은 탭과 헤더에 텍스트로 표시하며, 활성 탭은 새 라벨 측정 후 보이도록 스크롤한다.

## 알림

권한/질문 이벤트는 **발생 관측**이며 현재 CLI가 대기 중이라는 보장은 아니다. 세션 화면으로 돌아가 직접 결정한다. 앱 안의 기록과 잠금 해제된 알림에는 프로젝트와 세션 이름을 표시한다. 시스템 알림은 PRIVATE 가시성과 이름 없는 publicVersion을 사용하여 잠금 화면의 민감 정보 숨기기 정책을 따른다. 잠금 화면에서의 최종 표시는 사용자의 Android 알림 공개 설정과 제조사 동작을 추가 검증한다. 명령·질문·대화·토큰은 수집하지 않는다.

진단 ACK는 최대 5초를 기다린다. 응답을 잃었더라도 동일 launch/event ID의 실제 수신 기록이 있으면 수신 결과와 알림 게시 상태를 분리해 표시한다. 다른 알림이 있다는 이유로 진단을 성공 처리하지 않는다. CLI hook 자체의 지연 예산은 기존 0.45초를 유지하며 승인 결정을 반환하지 않는다.

알림 기록은 최대 256개다. 한도에 도달하면 가장 오래된 읽음·작업 완료·종료 세션 기록부터 새 이벤트로 교체한다. 활성 세션의 미확인 요청만으로 가득 차면 기존 요청을 지우지 않고 새 이벤트를 거절한다. 교체 중 저장이 실패하면 기존 기록과 순서를 복원하며, CLI의 승인 결과를 바꾸지 않는다.

## 검증 범위

- 호스트: 실제 `Z8TerminalInput` 클래스를 컴파일하여 정방향/역방향/scrollback 선택, 취소·세션 이동 후 상태 초기화, 한글 단일 입력, 여러 줄/CRLF/Enter 정책과 16가지 modifier 조합을 실행한다. 생성된 TerminalView의 실제 shortcut 메서드도 Java harness에서 실행하여 Cmd+C 선택 유무, Cmd+V 반복 억제, Ctrl+C/V 미가로채기, 빈 터미널을 확인한다.
- 호스트: 실제 `Z8WorkspaceKeys` 클래스로 생성·탭 이동·브라우저 전용 키, 일반 터미널 입력 보존, 반복·해제·취소, 여러 키보드와 포커스 초기화를 실행한다. `Z8TerminalInput`의 소수점 스크롤 누적·경로 전환·상한과 생성된 TerminalView의 로컬 viewport 갱신도 확인한다. 이 테스트는 실제 Android가 물리 키를 앱에 전달하는지까지 검증하지 않는다.
- 고정 upstream에 패치가 모두 적용되는지, 앱의 붙여넣기 경로가 통합되는지 회귀 계약을 검사한다.
- `tools/inject-pointer.py`는 전용 AVD에 `SOURCE_MOUSE`, `buttonState`, Shift 메타데이터가 있는 합성 이벤트를 주입한다. 앱을 재시작하거나 명령을 입력하지 않는다. 좌표는 현재 화면 캡처에서 읽어 전달한다.
- Android 실행 검증은 새 APK 설치 뒤 별도 결과 파일에 기록한다. 소스 검사와 합성 마우스 이벤트를 물리 마우스·Samsung IME 검증으로 표현하지 않는다.
- 실기기 잔여: USB/Bluetooth 마우스, trackpad, Samsung 한글 조합과 clipboard chip, 폴드 전환 중 핸들 위치, 접근성 도구의 실제 입력 전달.

### AVD 재검증 순서

1. 폐기 가능한 Terminal에서 식별 가능한 텍스트를 출력하고 `tools/inject-pointer.py drag`로 실제 화면 좌표의 문자열을 선택한다. Ctrl+Shift+C를 전달한 뒤, 같은 Terminal의 비실행 입력 영역에 Ctrl+Shift+V로 선택한 문자열이 한 번 들어오는지 확인한다. Enter는 자동 주입하지 않는다. Meta+C/V는 별도 호환성 항목으로 확인하며 시스템이 소비하면 제한 사항으로 기록한다.
2. 선택을 닫고 Ctrl+Shift+C를 누른다. 장기 실행 중인 테스트 프로세스가 중단되거나 문자 `c`가 입력되지 않아야 한다. 같은 테스트 프로세스에서 Shift 없는 Ctrl+C는 정상 중단되어야 한다. Meta 이벤트가 앱에 전달되는 환경에서는 선택 없는 Meta+C도 같은 무입력 동작인지 확인한다.
3. 마우스 보고 테스트 TUI에서 기본 드래그는 TUI 이벤트, Shift+드래그는 로컬 선택이 되는지 확인한다. 드래그 도중 Shift를 놓아도 이미 선택한 경로를 유지해야 한다.
4. SOURCE_TOUCHSCREEN 길게 누르기로 선택 툴바의 복사/붙여넣기를 사용하고, 여러 줄 붙여넣기 확인창에서 다른 프로젝트로 전환하면 원래 내용이 새 PTY에 들어가지 않는지 확인한다.
5. 위 합성 검증 후 별도로 Mac 호스트 Cmd 전달과 물리 Android 외장 키보드를 확인한다. 합성 결과를 물리 장치 호환성으로 기록하지 않는다.
6. 같은 프로젝트에 두 터미널과 브라우저 탭을 열어 Ctrl+Tab으로 `Terminal 1 → Terminal 2 → 브라우저 → Terminal 1`, Ctrl+Shift+Tab으로 역순 이동을 확인한다. Ctrl+Shift+T를 누른 채 반복 이벤트를 보내도 터미널이 하나만 생겨야 한다. 브라우저에서 Ctrl+L/R·Esc를 확인한 뒤 터미널에서 Ctrl+R·Esc가 CLI로 전달되는지 확인한다.
7. 두 터미널 중 현재 선택하지 않은 쪽에서 소유한 진단 브라우저 요청을 보내 z8 위의 브라우저 창을 연다. 창을 닫으면 그 요청을 보낸 정확한 터미널이 선택되고 새 PTY가 생기지 않아야 한다. 실제 Claude 인증 성공 여부는 이 진단 요청과 별도로 기록한다. 로컬 미리보기는 홈 화면을 다녀와도 브라우저 탭과 페이지를 유지하는지 확인한다.
8. 소수점 수직 스크롤을 여러 번 주입해 누적 후 행이 이동하는지, 수평값만 있는 이벤트는 세로 이동을 만들지 않는지 확인한다. Shift·mouse reporting 경로 전환과 세션 전환 뒤 이전 잔여량이 섞이지 않아야 한다. 물리 트랙패드의 가속·관성 느낌은 실제 장치에서 별도로 확인한다.
