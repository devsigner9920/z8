# 최적화 검증 기록

2026-10-11. 아래는 구현된 작업량 제한과 자동 검증 범위다. 전력 소비, 발열, 실제 기기 배터리 시간의 개선치는 측정하지 않았다. 에뮬레이터 화면·수치 증거와 APK 해시는 검증 완료 후 별도 실행 기록에 연결한다.

## 구현한 변경

| 영역 | 작업량과 수명주기 | 검증 근거 |
| --- | --- | --- |
| CPU 표시 | 화면에서 표시할 때 3초 간격으로 앱 프로세스 CPU 카운터를 읽는다. 화면을 다시 보이면 기준값을 새로 잡는다. | `Z8ResourceMonitor`, `test_resource_monitor.py` |
| RAM 표시 | PSS 읽기는 15초 간격이며 화면 복귀 시 즉시 측정한다. CPU 갱신 사이에는 최근 PSS 값을 재사용한다. | 지속 표시 구간의 명목상 PSS 호출 빈도는 3초마다 읽을 때보다 80% 적다. 실제 실행 시간·소비 전력 감소율은 아니다. |
| 표시 전달 | 메인 스레드가 바쁠 때 대기 중인 자원 표시 콜백을 하나로 합치고 최신 샘플만 전달한다. | 수명주기·전달 테스트에서 중지 후 지연 전달과 이전 세대 샘플을 배제한다. |
| 알림 목록 | 최대 256개 이벤트의 열기 가능 여부를 한 번에 조회하고, 세션별 목록을 맵으로 묶는다. | 이벤트마다 전체 목록을 다시 찾는 최악의 O(n²) 조회가 O(n) 조회로 바뀐다. 시간순 정렬은 별도의 O(n log n) 작업으로 남는다. |
| 웹 미리보기 | 로컬 미리보기를 실제로 열 때 WebView 하나를 생성한다. 비활성·백그라운드에서는 타이머를 정지하고 프로젝트 전환·닫기에서 제거한다. | 수명주기 코드와 에뮬레이터 전환 검증으로 확인한다. 페이지 자체의 소비 자원은 별개다. |
| 브라우저 요청 | 세션당 1개, 전체 16개, 2분 유효기간. 소켓 전송은 한 번만 시도하고 대기 시간을 제한한다. | `test_browser_bridge.py`: 실제 Unix 소켓 전달, 지연 서버, 중복·상한·만료·종료 세션 검증 |
| 마우스·트랙패드 스크롤 | 휠 한 칸당 3행과 소수 단위 이동을 누적하며 수평 입력을 수직 스크롤로 바꾸지 않는다. 이벤트당 최대 120행으로 제한한다. | 로컬 스크롤백 100행 입력을 화면 위치 변경 1회와 다시 그리기 1회로 합친다. TUI 보고·Shift 동작은 별도로 보존한다. |

상단 CPU·RAM 수치는 **z8 Android 앱 프로세스**만 표시한다. PRoot의 Linux 프로세스, 터미널이 시작한 개발 서버, 외부 Chrome 전체를 합한 값이 아니다. CPU는 사용할 수 있는 코어 전체를 100%로 계산하며 RAM은 PSS다. 이 수치를 기기 전체 또는 프로젝트 전체 사용량으로 해석하지 않는다.

## 자동 검증 범위

이 문서 작성 시 확인된 개별 실행 결과:

- 브라우저 브리지 테스트 10개 통과: HTTP(S) 경계, 민감 URL 비출력, 실제 소켓 전달, 제한 시간, 사용자 브라우저 기본값 유지, 전면 UI 소비, 종료·만료 세션, 용량·중복 처리.
- 브라우저·guest 이미지 준비·기존 훅 실행기 관련 테스트를 함께 실행한 28개 통과.
- 최적화 담당 검증의 자원 표시 1개 및 알림 목록 5개 테스트 통과. 하나의 테스트 안에서 여러 수명주기·수치 시나리오를 확인한다.
- 터미널 입력 테스트 2개 통과: 생성된 실제 Java 입력 어댑터를 실행해 소수 휠 이동, 수평 입력, 세션·기기 전환 시 누적 초기화, 화면 갱신 횟수와 TUI 보고를 확인했다. 물리 마우스·트랙패드 검증 결과는 아니다.

이 결과는 실제 Android 브라우저 인증, GPU 렌더러 성능 또는 배터리 수명 테스트를 대신하지 않는다. 최종 통합 테스트 개수는 최종 APK와 함께 실행한 기록을 사용한다.

## 에뮬레이터 결과 기입 항목

| 항목 | 기록할 증거 | 상태 |
| --- | --- | --- |
| 실행 환경 | APK SHA-256, AVD, Android/API, 메모리·코어·GPU 옵션, 브라우저/WebView 제공자 버전 | 최종 실행 기록에 기입 |
| 첫 실행 | 빈 프로젝트 화면 → 자동 준비 → 터미널, 각 단계 캡처 | 최종 실행 기록에 기입 |
| 브라우저 연결 | 자격 증명 없는 예제 URL, 실제 브라우저 패키지, 원래 세션 복귀 | 최종 실행 기록에 기입 |
| 로컬 미리보기 | 실제 PRoot 개발 서버의 응답, 접기·펼치기, 터미널로 전환 | 최종 실행 기록에 기입 |
| 미리보기 종료 | 프로젝트 전환·탭 닫기 후 남은 페이지 또는 잘못된 세션 복귀 여부 | 최종 실행 기록에 기입 |
| 백그라운드 | 미리보기 비활성 시 타이머 정지, 터미널 작업 생존 | 최종 실행 기록에 기입 |
| UI 성능 | 같은 기기·작업·출력량에서 반복 측정한 프레임 시간과 메모리 | 아직 전후 성능 비교 미측정 |
| 실제 인증 | 사용자 계정 인증 완료와 CLI 복귀, 실패 시 코드 입력 경로 | 별도 계정 기반 검증 필요 |
| 실제 기기 전력 | 동일 화면 밝기·네트워크·온도·작업에서 장시간 비교 | 미측정 |

에뮬레이터 결과에는 설치된 APK에 대한 관찰만 기록한다. 이전 APK의 검증, 호스트 단위 테스트, 실제 기기 검증을 하나의 성공 결과로 합치지 않는다. 로그인 URL·OAuth 코드·토큰·사용자의 브라우저 계정 화면을 결과 파일에 넣지 않는다.
