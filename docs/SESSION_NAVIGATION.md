# 프로젝트와 세션 탐색

2026-10-17 구현 기준으로 갱신. 2026-10-05 사용자 선택에 따라 별도 워크스페이스 홈과 파일·Git·GitHub UI를 제거하고 터미널을 앱의 시작 화면으로 사용한다. Git과 GitHub는 표준 환경에 자동 준비되는 CLI 도구다. 과거 화면·검증 링크는 당시 APK의 증거로 유지한다.

z8 터미널 화면은 프로젝트별 세션 목록과 현재 프로젝트의 탭으로 구성한다. 프로젝트를 오가거나 다른 도구의 터미널을 선택해도 실행 관리는 기존 Termux 서비스가 담당한다. 상단에는 프로젝트 이름만 표시하며 `LOCAL / 이 기기` 부제는 제거했다.

`Prism` 테마는 블루·라일락·핑크·오렌지 색을 브랜드, 선택된 행과 탭 밑줄에 사용한다. 탭의 채워진 색상판과 세션 추가 버튼의 그라데이션 타일은 제거했다. 버튼은 누를 때 Android의 짧은 ripple로 반응하며 상시 애니메이션은 없다. 터미널 본문은 단색 배경이고 기존 Midnight·Graphite·Ember·Paper도 유지한다. [이전 화면 개편 기록](design/UI_REFINEMENT.md)의 캡처는 당시 APK 기준으로 유지한다.

테마 설정은 넓은 화면에서 터미널 미리보기와 선택 목록을 나란히, 좁은 화면에서 미리보기 아래에 색상 카드를 배치한다. 테마를 누르면 미리보기만 바뀌며 적용 전 뒤로 가면 기존 설정을 유지한다. 선택 컨트롤은 다시 만들지 않아 키보드 포커스를 보존하고 접기·펼치기에도 선택을 복원한다. 신규 설치와 설정 화면의 2026-10-05 검증 기록 (비공개 내부 검증 기록: `reports/design/2026-10-05/theme-picker/validation.json`)에 실제 캡처와 검증 범위를 남겼다.

## 화면과 조작

| 위치 | 동작 |
| --- | --- |
| 왼쪽 위 메뉴 아이콘 | 프로젝트·세션 패널 열기. 넓은 화면에서는 사이드바 표시 전환 |
| 프로젝트 제목 | 마지막으로 보던 기존 세션으로 이동. 기억한 세션이 없으면 다른 기존 세션, 세션이 없으면 프로젝트만 선택하고 빈 터미널 영역 표시 |
| 프로젝트 옆 펼침 아이콘 | 해당 프로젝트의 세션 목록만 접기·펼치기 |
| 프로젝트 아래 세션 행 | 해당 프로젝트의 기존 세션 선택 |
| 상단 가로 탭 | 현재 프로젝트 안에서 기존 세션 전환 |
| 마지막 탭 옆 추가 아이콘 | 선택한 프로젝트에 새 Terminal 열기. 해당 프로젝트에 탭이 있을 때만 표시 |
| 프로젝트 옆 추가 아이콘 | 해당 프로젝트에 새 Terminal 바로 열기 |
| 패널의 `프로젝트` 머리글 옆 추가 아이콘 | 이름을 입력해 새 프로젝트를 만들고 환경 준비 후 첫 Terminal 열기 |
| 탭·세션 행 길게 누르기 | 이름 변경·최근 출력 복사·알림·터미널 종료 메뉴 |
| 프로젝트 제목 길게 누르기 | 프로젝트 전체 삭제 확인. 실행 중인 터미널이 있으면 `모두 종료하고 삭제`로 함께 종료한 뒤 삭제 |
| 패널 z8 로고 오른쪽 알림 아이콘 | 프로젝트·세션별 알림 목록 열기. 항목을 누르면 발생한 터미널로 이동 |
| 상단 톱니바퀴 | 설정 열기. 테마·단축키 안내·시스템 알림 설정 제공 |

선택한 프로젝트에 탭이 없으면 상단 탭 줄을 숨긴다. 첫 터미널은 프로젝트 목록에서 이름 옆 추가 아이콘으로 연다. 탭이 생기면 마지막 탭 옆에 추가 아이콘을 표시한다. 탭이 화면 너비를 채우면 탭 영역만 가로로 스크롤되고 추가 아이콘은 오른쪽에 남아 항상 누를 수 있다. 선택된 탭은 2dp 강조색 밑줄로 표시하며 선택 탭이 보이도록 스크롤한다. 탭 배경은 터미널과 이어지고 전체 너비의 구분선은 그리지 않는다. 일반 터미널의 기본 이름은 프로젝트별 `Terminal 1`, `Terminal 2` 순서로 지정하며, 삭제하거나 이름을 바꾼 터미널의 번호는 다시 쓰지 않는다. 사용자 지정 이름이 겹치면 표시용 번호로 구분한다. 다른 프로젝트로 전환하려면 패널의 프로젝트 제목이나 그 아래의 세션을 누른다.

탭은 최소 80dp·최대 180dp 너비이며, 중립색 추가 아이콘은 18dp다. 탭과 추가 버튼의 실제 터치 영역은 48dp 높이를 유지하고 누름·키보드 포커스 표현은 32dp 높이 안에 배치한다. 시각적 두께를 줄이면서 터치와 외장 키보드 접근성을 유지한다.

프로젝트 제목을 누르면 해당 프로젝트에서 마지막으로 보던 살아 있는 세션을 선택한다. 이 기억은 현재 터미널 화면의 수명에 한정하며, 기억한 세션을 사용할 수 없으면 다른 기존 세션을 선택한다. 기존 세션이 없으면 다른 세션의 실행은 유지하면서 선택한 프로젝트의 빈 터미널 영역을 보여준다. 프로젝트 제목 선택 자체는 새 세션을 만들지 않는다. 옆의 별도 48dp 펼침 버튼은 목록만 접거나 펼치며 세션을 전환하지 않는다.

일반 세션 행은 최소 48dp 높이에 이름 한 줄과 터미널 아이콘을 배치한다. 선택 행은 배경과 글자색으로 구분한다. 미확인 요청 또는 종료 상태가 있을 때만 두 번째 상태 줄을 표시하며, 미확인 요청은 세션 행의 숫자 배지와 탭의 숫자로도 보여준다. 패널 하단의 큰 `새 세션` 버튼은 제거하고, 상단과 각 프로젝트의 추가 버튼을 사용한다.

탐색 아이콘은 문자 기호 대신 공식 Google Material Icons Outlined VectorDrawable을 사용한다. 출처와 라이선스, 원본 경로 보존 여부는 [아이콘 출처](design/ICON_SOURCES.md)에 기록한다. Claude Code와 Codex 행도 일반 터미널 아이콘을 사용하며 별도 브랜드 로고를 포함하지 않는다. 아이콘 버튼은 접근성 이름과 툴팁을 제공하고, 누름 효과와 외장 키보드 포커스 테두리를 적용한다.

기존 터미널 문맥 메뉴의 `세션 목록 / 새 세션`은 같은 진입점으로 유지한다. Termux 원본의 `NEW SESSION`·`KEYBOARD` 목록은 화면에서 숨기며, 새로 노출하는 하단 ESC·CTRL·방향키 바는 없다. 보조 키 바는 기본으로 숨긴 상태를 유지한다.

## 폴더블과 창 크기

### 헤더 리소스 표시

프로젝트 제목 오른쪽의 여유 공간에는 `앱 CPU …% RAM … MB`를 한 줄로 표시한다. 숫자 폭을 고정하고 중립색 텍스트만 사용한다. 헤더 내부 폭이 520dp 미만이거나 전체 프로젝트 이름을 표시할 공간이 부족하면 리소스 표시를 숨긴다. 측정값이 바뀔 때 제목이나 메뉴 위치는 이동하지 않는다.

측정 범위는 **현재 z8 Android 앱 프로세스**다. [Process.getElapsedCpuTime](https://developer.android.com/reference/android/os/Process#getElapsedCpuTime())의 CPU 시간 차이를 경과 시간과 앱이 사용할 수 있는 코어 수로 나누며, 해당 코어 전체를 사용할 때 100%다. [Debug.getPss](https://developer.android.com/reference/android/os/Debug#getPss())의 메모리 값은 공유 페이지를 비례 배분한 PSS이며, KiB를 십진 MB·GB로 변환한다. 터미널·PRoot·Python·Node 등 별도 하위 프로세스나 기기 전체 사용량은 포함하지 않는다. 이 범위를 표시 이름, 접근성 설명, 누르기 안내와 툴팁으로 알린다.

측정은 화면과 표시 영역이 보일 때만 별도 작업 스레드에서 3초 간격으로 수행한다. 접힌 화면·백그라운드·화면 종료에서는 중단한다. 다시 표시할 때 CPU 기준 시점을 새로 잡으며, 첫 샘플과 측정 불가 값은 `—`로 표시한다. 측정 중 화면이 닫힌 경우 늦게 도착한 결과를 버린다. 계산·수명주기 동작은 `tests/test_resource_monitor.py`로 검증하며, 이 단위 검증은 기기별 수치 정확성이나 실제 UI 캡처를 대신하지 않는다.

### 반응형 배치

실제 사용 가능한 창 너비가 **720dp 이상**이면 248dp 사이드바와 터미널을 나란히 배치한다. 720dp 미만이면 사이드바를 숨기고 메뉴 아이콘으로 여는 슬라이드 패널을 사용한다. 화면 해상도나 기기 모델명 대신 현재 창 너비를 기준으로 하므로 접기·펼치기와 분할 화면에도 같은 규칙을 적용한다.

Termux Activity는 화면 크기 변경을 직접 처리한다. Chrome은 실제 레이아웃 너비가 달라질 때 패널 폭과 표시 방식을 갱신하고, 기존 `TerminalView`와 세션을 유지한다. 넓은 화면에서는 중복 슬라이드 패널을 잠그며, 텍스트 복사 모드가 끝나도 이 규칙을 유지한다. 외장 키보드의 `Ctrl+Alt+→`도 같은 패널 진입점으로 연결한다.

키보드가 열리는 등 사용 가능한 높이가 480dp 미만이 되면 패널 상단과 프로젝트 머리글의 여백을 줄인다. z8 로고와 알림 버튼, 프로젝트·세션 목록을 유지하고 높이가 돌아오면 여백을 복원한다. 하단 응답·테마 버튼은 없으며, 테마는 상단 톱니바퀴의 설정 화면에서 연다.

## 세션 추가와 이름

탭 줄의 추가 아이콘은 **선택한 프로젝트에 새 Terminal을 연다**. 프로젝트 옆 추가 아이콘도 해당 프로젝트에 바로 터미널을 연다. 새 세션 생성에는 프로젝트 선택창이나 도구 선택창이 없다. 최초 앱 설정에서 동의한 기본 환경을 준비하고, 새 프로젝트는 준비된 환경을 독립적으로 복사한 뒤 첫 Terminal을 연다. 기본 환경이 아직 없거나 기존 프로젝트의 환경 준비가 미완료이면 같은 준비 흐름을 사용한다. 별도 환경 관리 화면이나 기기 셸을 열지 않으며, 터미널 영역에서 단계와 진행 막대를 보여준다. 패키지 다운로드는 전체 백분율을 추정하지 않는다. 실패하면 오류와 재시도를 제공한다. 중단된 최초 설치·프로젝트 준비는 다음 사용자의 앱 실행에서 완료된 단계를 검증하고 미완료 단계부터 복구할 수 있으며, 일반 셸 명령·AI 작업을 자동 재실행하지 않는다. 상세 범위는 [설치 생명주기](PREPARATION_LIFECYCLE.md)를 따른다.

새 세션 생성이 대기 중인 동안 추가 버튼을 잠시 비활성화한다. 빠르게 연속으로 누른 입력도 중복 생성 요청으로 이어지지 않도록 처리한다.

선택한 프로젝트에 탭이 없으면 상단 탭 줄과 추가 아이콘을 숨긴다. 패널에서 원하는 프로젝트 옆 추가 아이콘을 누르면 그 프로젝트에 새 Terminal을 연다. 새 프로젝트를 만들 때의 이름 입력 대화상자는 유지한다.

Claude Code·Codex는 필요한 CLI를 명시적으로 설치한 뒤 터미널에서 실행한다. 개발 빌드의 `설정` → `현재 프로젝트 환경`에도 설치·실행 버튼을 제공한다. 최초 기본 환경 설치에는 두 AI CLI가 포함되지 않으며 기본 AI 탭이나 자동 실행도 없다. 탭은 사용자가 만든 실제 터미널 세션을 표시한다. 미설치 상태를 숨기거나 임의로 다운로드하지 않으며, 환경 준비나 실행이 실패하면 오류를 표시한다. 세션 관리 메뉴와 이름 변경·종료 확인창은 현재 테마를 적용하고 종료 동작을 별도 경고색으로 표시한다. 설치·로그인·sandbox 호환성은 [AI 도구 안내](../runtime/guest/AI_TOOLS.md)의 범위를 따른다.

이 화면에서 만드는 세션은 해당 프로젝트의 `/z8/home`에서 시작하며 소스는 `/workspace`에 있다. 파일·Git·GitHub 별도 화면은 제거했다. 프로젝트나 세션을 바꿀 때 실행 중인 터미널에 `cd` 또는 다른 문자열을 입력하지 않는다.

세션의 도구 표시는 생성할 때 선택한 실행 목적이다. Claude Code·Codex 실행·설치 작업이 끝나면 실제 종료 코드와 출력을 보존하고 종료 상태를 표시한다. 임의로 일반 셸을 이어 열지 않는다. 설치 작업은 `Codex 설치`·`개발 도구 설치` 등으로 구분한다. 프로젝트 연결이 없는 Android 셸은 `기기 셸` 그룹에 표시한다.

`이름 변경`은 기존 세션의 이름만 바꾸며 새 PTY를 만들지 않는다. 제어문자와 방향성 제어문자를 제거하고 제목 길이를 제한한다. 변경된 이름과 그룹 연결은 현재 프로세스의 세션 객체에 보관한다. 현재 터미널 목록은 최대 8개이며, 이미 종료되어 목록에 남은 항목은 명시적으로 제거할 수 있다.

| 표시 | 의미 |
| --- | --- |
| 일반 세션 행, 접근성 설명의 `세션 열림` | 해당 터미널의 프로세스가 살아 있음. 화면에는 반복되는 상태 줄을 생략 |
| `미확인 알림 N개`, 행의 숫자 배지 및 탭의 숫자 | 살아 있는 해당 세션에 연결된 미확인 권한·질문·계획 훅 이벤트가 수신됨 |
| `종료됨` | 해당 터미널 프로세스가 끝났으나 항목이 아직 목록에 남아 있음 |

PTY 프로세스 상태만으로 AI의 작업 중·완료·승인 대기를 추측하지 않는다. 요청 표시는 훅 수신기에 들어온 이벤트에 근거하며 터미널 출력이나 대화 내용을 파싱하지 않는다. 완료 이벤트는 요청 수에 포함하지 않는다. 화면이 보일 때만 요청 수를 주기적으로 가져오며, 훅 수신기의 저장 잠금을 기다리는 작업은 UI 스레드 밖에서 수행한다.

탭을 선택하는 것만으로 요청을 처리했다고 기록하지 않는다. `알림` 목록에서 요청의 해당 세션을 여는 흐름으로 확인 상태를 기록한다. 확인 표시가 사라져도 CLI에 승인 응답을 보낸 것은 아니다. 사용자는 연결된 실제 터미널에서 내용을 읽고 답한다. 합성 이벤트로 시험한 전달과 실제 AI CLI가 생성한 요청은 검증 기록에서 구분한다.

## 터미널의 HTML 경로 미리보기

출력에 표시된 `dist/index.html` 같은 `.html`·`.htm` 경로를 짧게 탭하면 앱 내 브라우저로 미리본다. 현재 프로젝트의 HOME과 소스에서 같은 경로로 끝나는 파일을 확인하며, 검색을 끝냈고 한 파일만 발견했을 때 자동으로 연다. 같은 경로가 여러 곳에 있으면 전체 프로젝트 경로가 표시된 목록에서 선택한다. `/z8/home/…`·`/workspace/…` 절대 경로는 프로젝트 경계를 확인한 뒤 직접 연다.

PRoot의 `/proc` 경로를 실제 게스트의 현재 폴더라고 간주하지 않는다. 검색은 UI 밖에서 실행하며 숨김 폴더, `node_modules`, `venv`, `__pycache__`, 심볼릭 링크를 제외한다. 깊이 10단계·항목 12,000개·2초·후보 20개 제한에 도달하면 파일을 임의로 고르지 않고 전체 HTML 경로를 사용하도록 안내한다. 파일과 부모 경로는 열기 직전에 다시 검사한다.

파일 열기는 별도 실행기로 기존 HTML 미리보기 연결을 호출한다. 실행 중인 Claude·Codex·셸 입력창에 명령을 쓰거나 Enter를 보내지 않는다. 미리보기 서버는 원래 터미널의 수명과 기존 유휴·최대 시간 제한을 따른다. 길게 누르기, 선택 핸들 이동, 스크롤, 확대·축소는 파일 열기가 되지 않는다. 일반 셸의 마우스 클릭도 지원하지만, TUI가 실제 마우스 이벤트를 요청할 때는 그 프로그램의 기존 클릭 동작을 유지한다. 한 줄에 보이는 공백 없는 파일 경로를 대상으로 하며, 줄바꿈된 경로와 공백이 있는 경로는 `xdg-open`으로 명시해서 열 수 있다.

## 실행 유지와 종료

세션 전환은 서비스 목록에 여전히 존재하는 **동일한 TerminalSession 객체**를 선택해 기존 TerminalView에 연결한다. 이름 변경·종료 직전에도 서비스가 그 객체를 소유하는지 다시 확인한다. 오래된 화면 항목이 다른 세션을 대상으로 동작하지 않도록 handle 문자열만으로 대상을 바꾸지 않는다.

다른 탭 선택·프로젝트 선택·패널 닫기는 실행 중인 프로그램을 종료하지 않는다. 명시적인 `터미널 종료…`를 선택하면 별도의 확인 후 해당 터미널 프로세스를 종료한다. 종료된 항목의 `목록에서 제거`는 프로젝트 파일을 삭제하지 않는다. 셸이 정상 종료한 경우에는 기존 Termux 종료 정책에 따라 항목이 자동으로 제거될 수도 있다.

프로젝트 제목을 길게 눌러 삭제하면 소스·HOME·Linux 환경·프로젝트 설정을 함께 지운다. 열린 터미널은 확인창의 `모두 종료하고 삭제`로 한 번에 종료할 수 있다. 준비·종료·삭제 작업이 충돌하면 기다리도록 안내하고, 대상 프로세스의 종료를 확인하지 못하면 파일을 삭제하지 않는다. 개별 세션 종료와 프로젝트 전체 삭제는 별도 동작이다.

이 연결 유지의 전제는 앱 서비스와 해당 PTY 프로세스가 살아 있다는 것이다. OS의 프로세스 회수·강제 종료·재부팅 뒤의 셸, 터미널 출력, AI 대화를 복원하는 영속 세션 기능은 아직 제공하지 않는다. 이름과 프로젝트·세션 연결도 현재 프로세스에 한정한다. tmux 실행 시험과 제품의 자동 tmux 세션 관리는 별도이며, 세션 UI가 후자를 구현했다는 의미는 아니다.

## 구현과 검증 기록

화면은 `Z8SessionChrome`, 탐색 화면의 테마색·누름 효과·포커스 표현은 `Z8ChromeStyle`, 표시용 메모리 스냅샷은 `Z8SessionCatalog`, 생성 출처는 `Z8SessionOrigin`이 맡는다. `Z8ChromeStyle`은 선택한 터미널 테마의 밝기와 강조색을 참고하며 터미널 색상이나 설정을 변경하지 않는다. `tools/prepare-app.py`가 Termux Activity의 화면 설치·복귀·종료와 세션 변경 통지를 연결한다. 화면이 보이지 않으면 갱신 타이머를 중단하고, Activity가 파괴되면 작업 executor와 callback을 정리한다. 선택·생성 요청의 프로젝트 ID는 프로젝트 저장소의 실제 목록과 대조한다.

2026-10-04 디자인 검증 기록 (비공개 내부 검증 기록: `reports/design/2026-10-04/session-navigation.json`)은 당시 화면 개편의 APK 식별자와 실행 증거를 보관한다. 2026-10-17 문서 갱신은 현재 코드의 동작을 정리한 것이며, 과거 기록을 현재 APK의 통과 결과로 전용하지 않는다. 현재 회귀 결과는 날짜별 `reports/compatibility/` 기록의 APK 해시와 실제 실행 범위를 확인한다.

초기 모달 없는 동작의 2026-10-04 검증 (비공개 내부 검증 기록: `reports/design/2026-10-04/direct-session/project-selection.json`)은 세 진입점에서 각각 Shell 하나 생성, 프로젝트 이름으로 마지막 세션 재연결, 접힌 화면에서 같은 PID 유지까지 확인한다. 실행 및 화면 증거의 APK 해시는 별도로 기록했다.

프로젝트·도구 선택창을 사용하던 이전 APK의 별도 검증 (비공개 내부 검증 기록: `reports/design/2026-10-04/project-selection/project-selection.json`)은 당시 두 선택 단계의 프로세스 미생성, 취소 후 동일 PID, 다른 프로젝트에 명시적인 Shell 생성, 접힌 화면의 선택창을 확인한 역사적 기록이다. 현재의 모달 없는 Shell 생성 동작에 대한 검증으로 해석하지 않으며, 각 APK와 시험 범위는 기록의 해시로 구분한다.

기존 세션 UI 검증 기록 (비공개 내부 검증 기록: `reports/compatibility/session-navigation.json`)은 화면 개편 전 빌드의 역사적 기록으로 유지한다. 여기의 접기·펼치기, 동일 프로세스 유지, 이름 변경·종료·요청 표시 결과는 기록에 명시된 APK와 시험 범위에만 적용한다. 기존 Linux 연속성 기록 (비공개 내부 검증 기록: `reports/compatibility/guest-continuity.json`)도 같은 원칙을 따른다. 현재 사용 문서만으로 통과 판정이나 테스트 개수를 정하지 않는다.

## Orca 참고 출처

Orca의 프로젝트/세션 헤더, 가로 탭, 탭 길게 누르기 탐색 구성을 참고했다. 추가 버튼은 z8에서 탭이 있을 때만 마지막 탭 옆에 표시하도록 조정했다. 구체적인 기준은 고정 커밋 `2b1acd0d0e686a5a59627920d62153a95ecf8fa7`의 [MobileSessionHeader.tsx](https://github.com/stablyai/orca/blob/2b1acd0d0e686a5a59627920d62153a95ecf8fa7/mobile/src/session/MobileSessionHeader.tsx)다. z8 화면은 Android 네이티브 뷰와 기존 로컬 PTY 서비스에 맞춰 구현한다.

[Orca 공식 모바일 문서](https://www.onorca.dev/docs/mobile)는 데스크톱과 페어링하는 companion 구조와 모바일 탭 조작을 설명한다. z8는 Android 기기 자체에서 개발 환경을 실행한다. Orca의 원격 연결·Chat UI·계정 전환·일괄 탭 닫기까지 z8에 구현되었다는 의미로 해석하지 않는다.
