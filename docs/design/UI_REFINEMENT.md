# z8 세션 화면 정리

2026-10-04. Product Design 점검과 Android 네이티브 구현을 함께 진행했다. 기존 프로젝트 사이드바·상단 세션 탭·실제 터미널 구조를 유지하고, 이 흐름의 밀도·강조·조작 피드백을 정리했다. 파일 편집기와 GitHub 화면 전체를 새로 디자인한 작업은 아니다.

## 판단과 변경

기존 화면은 선택된 행, 큰 아이콘 타일, 반복 상태 문구, 하단의 큰 추가 버튼이 동시에 강조됐다. 사용자가 읽어야 하는 프로젝트·세션 이름보다 주변 장식이 먼저 보였고, 키보드가 올라오면 완전한 세션 행이 두 개만 남았다.

- 248dp 사이드바와 최소 48dp 세션 행. 평소에는 이름 한 줄, 종료·미확인 요청이 있을 때만 상태 줄을 추가한다.
- 중립적인 차콜 배경, 단계별 글자 색과 작은 윤곽 아이콘. 선택된 탭은 2dp 밑줄, 선택된 행은 옅은 배경으로 구분한다. 사용자가 제공한 블루·라일락·핑크·오렌지 이미지를 사용하는 Prism 테마를 추가했고 기존 네 가지는 유지한다.
- 하단의 큰 중복 `새 세션` 버튼을 제거했다. 탭 옆의 고정 추가 버튼과 프로젝트 옆 추가 버튼으로 대상 프로젝트를 명확하게 선택한다.
- 도구 선택·세션 메뉴·이름 변경·종료 확인을 현재 테마와 맞춘다. 새 세션 선택에는 각 도구가 여는 작업을 짧게 설명한다.
- 아이콘 버튼의 터치 영역은 48dp이며, 누름 효과와 키보드 포커스 표시를 제공한다. 알림 갱신 때 같은 탐색 대상의 키보드 포커스를 보존한다. 탭의 접근성 설명에도 미확인 요청 수·종료 상태를 포함한다.
- 공식 Material 윤곽 아이콘의 출처와 Apache-2.0 고지를 [기록](ICON_SOURCES.md)하고 APK에 포함했다.

## 색과 터치 반응

사용자 제공 원본 PNG를 그대로 포함하고, Android에서 약 450×694로 한 번만 읽어 공유한다. 헤더에는 8%, 선택된 행에는 12%로 얹어 글자를 읽을 수 있게 했다. 브랜드 타일·선택 탭의 얇은 밑줄·새 세션 버튼은 원본 색을 선명하게 사용한다. 버튼 터치는 Android의 범위가 제한된 ripple로 짧게 퍼지고 사라진다. 상시 애니메이션·실시간 blur·주기적 이미지 디코딩은 없다. 터미널 출력은 단색 배경을 유지한다.

## 화면별 점검

같은 실행에서 ADB로 저장한 실제 화면을 직접 확인했다. 펼친 화면은 2208×1840, 접힌 화면은 1080×2092인 Android 17 / API 37 Pixel Fold ARM64 에뮬레이터다. 이전 화면은 Ember, 이후 화면은 새 Prism 테마다. 따라서 터미널 영역의 색 변화에는 테마 선택도 포함된다. 첨부 이미지는 색감 참고이며 전체 UI의 배치 시안은 아니므로 이미지와 앱 사이의 픽셀 일치를 주장하지 않는다.

### 1. 프로젝트와 세션 — 구조 유지, 시각적 무게 정리

이전 화면에서도 프로젝트 구분과 세션 전환은 가능했다. 큰 카드·상태 줄·중복 버튼을 줄여 이름과 현재 선택을 더 쉽게 훑도록 정리했다.

변경 전 프로젝트와 세션 (비공개 내부 검증 기록: `reports/design/2026-10-04/01-before-workspace.png`)

변경 후 프로젝트와 세션 (비공개 내부 검증 기록: `reports/design/2026-10-04/01-after-workspace.png`)

### 2. 새 세션 선택 — 주 화면과 테마 일치

기존의 흰 기본 대화상자를 테마를 따르는 도구 선택 창으로 바꿨다. 프로젝트 이름과 Shell·Claude Code·Codex의 짧은 설명을 함께 표시한다. 앱은 설치된 실제 CLI 실행 경로를 사용한다.

변경 전 새 세션 (비공개 내부 검증 기록: `reports/design/2026-10-04/02-before-create.png`)

변경 후 새 세션 (비공개 내부 검증 기록: `reports/design/2026-10-04/02-after-create.png`)

### 3. 접힌 화면 — 같은 탐색 구조, 가벼운 목록

좁은 창에서는 슬라이드 패널을 유지한다. 접기·펼치기를 기기 이름이 아니라 현재 사용 가능한 창 너비로 판단하며, 세션 전환과 화면 크기 변경은 기존 터미널 객체에 연결한다.

변경 후 접힌 화면 (비공개 내부 검증 기록: `reports/design/2026-10-04/03-after-folded.png`)

### 4. 키보드 표시 — 세션 탐색 공간 확보

사용 가능한 높이가 줄면 브랜드와 하단 보조 메뉴를 숨기는 기존 규칙을 유지했다. 짧아진 세션 행과 중복 버튼 제거로 남는 공간을 목록에 돌렸다. 시스템 키보드와 앱의 보조 키 바는 별개이며 앱의 ESC·CTRL 바는 기본 숨김을 유지한다.

## 검증과 한계

빌드 식별자는 build.json (비공개 내부 검증 기록: `reports/design/2026-10-04/build.json`), 실제 셸 PID와 세션 전환 검사는 session-navigation.json (비공개 내부 검증 기록: `reports/design/2026-10-04/session-navigation.json`), 추가 화면·입력 검사는 validation.json (비공개 내부 검증 기록: `reports/design/2026-10-04/validation.json`)에 기록한다. 변경 전 점검 내용은 audit.json (비공개 내부 검증 기록: `reports/design/2026-10-04/audit.json`)에 있다.

소스 색상 대비 수치는 contrast.json (비공개 내부 검증 기록: `reports/design/2026-10-04/contrast.json`)에 기록한다. 화면 캡처와 대비 계산만으로 접근성 전체 적합성을 주장하지 않는다. TalkBack의 전체 읽기 순서, 실제 외장 키보드, 한글 조합, 큰 글자 설정 전체, Galaxy 실기기의 제스처·배터리·장시간 생존은 별도 검증 대상이다.

이번 UI 검사는 AI 계정 로그인 이후 작업 성공, 실제 AI 권한 훅, 프로세스 사망·재부팅 후 복구를 입증하지 않는다. 기존 실행 범위와 남은 제약은 개발 빌드 기록 (비공개 내부 검증 기록: `reports/compatibility/G0_RUNTIME_BUILD.md`)을 따른다.


위 화면 개편 APK에서 터치 기반 탐색·입력 오류 처리·폴드 전환을 통과했다. 호스트 테스트 107개와 터미널 테스트 145개가 통과했다. ADB로 주입한 `Ctrl+Alt+→`는 터미널에서 목록으로 포커스가 이동하는 결과를 확인하지 못했다. 외장 키보드의 실제 이벤트와 진입 포커스는 다음 검증 대상으로 남긴다. 최종 화면 비교는 [design-qa.md](../../design-qa.md)에 있다.

## 이전 후속 수정: 프로젝트를 먼저 선택

상단 고정 `＋`는 현재 프로젝트를 자동 선택하지 않고 항상 프로젝트 목록부터 연다. 이후 선택한 프로젝트 이름과 함께 도구를 고르게 하며, 마지막 항목을 눌러야 실행한다. 두 창의 취소는 기존 세션을 유지한다. 프로젝트 행 옆 `＋`는 해당 프로젝트로 바로 연결된다.

이 문서의 앞선 Claude Code·Codex 탭은 개발자가 검증을 위해 명시적으로 연 세션이다. 기본 화면에 두 AI 탭이 자동 생성된다는 뜻이 아니다. 후속 APK와 실행 증거 (비공개 내부 검증 기록: `reports/design/2026-10-04/project-selection/project-selection.json`)는 별도 보관한다.

프로젝트 먼저 선택 (비공개 내부 검증 기록: `reports/design/2026-10-04/project-selection/project-picker.png`)

선택한 프로젝트의 도구 선택 (비공개 내부 검증 기록: `reports/design/2026-10-04/project-selection/tool-picker.png`)

## 현재 동작: 새 세션 모달 제거

앞선 프로젝트·도구 선택 모달은 사용자의 추가 의견에 따라 제거했다. 상단 `＋`는 현재 프로젝트, 프로젝트 옆 `＋`와 `첫 세션 열기`는 그 프로젝트의 Shell을 직접 연다. 프로젝트 제목은 마지막으로 보던 기존 세션으로 이동하고, 세션이 없는 프로젝트는 파일·Linux 환경 화면을 연다. 별도 화살표는 목록만 접고 펼친다. 새 프로젝트의 이름 입력창은 유지한다.

Claude·Codex는 Linux 환경 화면의 명시적인 실행 버튼 또는 터미널 명령으로 사용한다. Shell 생성 시 자동 실행하지 않는다. 준비 중인 요청과 짧은 연속 탭에는 중복 실행 방지를 적용했다.

모달 없이 새 Shell (비공개 내부 검증 기록: `reports/design/2026-10-04/direct-session/direct-session-opened.png`)

직접 생성 검증 (비공개 내부 검증 기록: `reports/design/2026-10-04/direct-session/project-selection.json`): API 37 에뮬레이터의 펼침·접힘 상태에서 실제 PID와 프로젝트별 HOME으로 확인했다. 호스트 테스트 113개와 빌드 터미널 테스트 145개가 통과했다. 이전 화면 검증은 해당 APK의 역사적 기록으로 유지한다.
