# 브라우저 탭과 CLI 인증

2026-10-17 구현 범위. 실제 계정으로 Claude Code 로그인을 완료했다는 검증 기록은 아직 없다.

z8의 브라우저 탭은 **로컬 개발 서버 미리보기**와 **z8 위에 표시되는 브라우저 소유 인증창**을 제공한다. 인증창은 설치된 Android 브라우저의 Custom Tab이며, 창을 닫으면 요청한 터미널로 복귀한다. 데스크톱 Chrome 전체를 Linux 환경 안에 설치하거나 앱 화면에 삽입하는 기능은 아니다. Chrome은 필수가 아니며, HTTP(S)를 열 수 있는 Android 브라우저가 필요하다.

| 시작 동작 | 표시 위치 | 현재 동작 |
| --- | --- | --- |
| 탭에서 `localhost:3000`, `127.0.0.1`, `[::1]`의 HTTP(S) 주소 입력 | z8 미리보기 탭 | Android System WebView를 필요할 때 생성한다. |
| 탭에서 외부 HTTP(S) 주소 입력 | z8 위의 브라우저 창 | Custom Tab으로 연결한다. 브라우저의 지원 여부에 따라 일반 브라우저 화면으로 열린다. |
| CLI의 `xdg-open about:blank` 요청 | z8 빈 브라우저 탭 | 주소를 입력할 수 있는 기존 브라우저 탭을 연다. WebView나 외부 브라우저를 실행하지 않는다. |
| CLI의 `xdg-open ./index.html` 또는 절대 HTML 파일 경로 | z8 미리보기 탭 | 선택 파일의 폴더에 한정된 루프백 HTTP 미리보기를 만든다. `.html`·`.htm`과 상대 경로 CSS·JS·이미지를 지원한다. |
| CLI의 `BROWSER`, `GH_BROWSER`, `xdg-open`에서 리터럴 루프백 HTTP(S) 요청 | z8 미리보기 탭 | `localhost`, `127.0.0.1`, `[::1]` 서버를 원래 프로젝트 안에서 연다. |
| 같은 CLI 실행기에서 외부 HTTP(S) 요청 | z8 위의 브라우저 창 | 프로젝트·터미널 출처를 유지한다. 외부 인증 URL은 WebView에 넣지 않는다. 쿼리나 경로에서 인증 여부를 추측하지 않는다. |
| 브라우저 미설치 / 사용 불가 | z8 안내 | 브라우저 설치 후 다시 열도록 안내한다. |

설치된 기본 브라우저가 Chrome이면 Chrome의 기능을 사용할 수 있다. z8는 특정 브라우저 패키지를 강제로 선택하지 않는다. 기본 앱이 정해져 있지 않으면 Android의 앱 선택 동작이 적용될 수 있다. Custom Tabs의 기능과 계정 상태는 이를 제공하는 브라우저에 따른다. [Android Custom Tabs 설명](https://developer.chrome.com/docs/android/custom-tabs)

## Claude Code 로그인

새 터미널에서 `claude`를 실행하고 CLI의 로그인 절차를 따른다. CLI가 브라우저 실행기를 호출하면 z8가 요청을 받아 브라우저 소유 인증창을 연다. 완료 후 창의 × 또는 뒤로 가기로 원래 세션에 복귀한다. 브라우저를 열었다는 사실만으로 로그인 완료라고 표시하지 않는다.

현재 PRoot 실행 경로는 별도의 네트워크 네임스페이스를 생성하지 않으며 Android 기기와 루프백 네트워크를 공유한다. 따라서 CLI가 같은 기기의 루프백 주소에 콜백 서버를 열면 기기 브라우저에서 접근할 수 있는 구조다. 이는 실행 구조에 근거한 설명이며, 실제 Claude 인증 콜백·계정 정책·브라우저 조합의 성공을 보장하는 실기기 검증은 아니다.

자동 열기가 되지 않으면 Claude의 로그인 URL을 복사해 기기 브라우저에서 연다. 현재 공식 문서는 로그인 화면에서 `c`로 URL을 복사하는 방법을 안내한다. 콜백 대신 브라우저에 로그인 코드가 표시되면 원래 CLI의 코드 입력란에 붙여 넣는다. 코드나 URL은 다른 프로젝트, 채팅, 검증 보고서에 붙여 넣지 않는다. [Claude Code 인증 문서](https://code.claude.com/docs/en/authentication)

인증 화면을 WebView에 직접 넣지 않는 것은 네이티브 앱 OAuth의 외부 사용자 에이전트 사용 원칙에 따른다. CLI가 OAuth 상태·콜백·토큰을 관리하며, z8 브리지는 브라우저 열기만 요청한다. [RFC 8252, 6·8.12절](https://www.rfc-editor.org/rfc/rfc8252)

## 터미널 연결 방식

새 터미널에는 다음 기본값을 전달한다.

```text
BROWSER=/usr/local/lib/z8/browser/bin/xdg-open
GH_BROWSER=/usr/local/lib/z8/browser/bin/xdg-open
PATH의 브라우저 실행 경로=/usr/local/lib/z8/browser/bin
```

Python 3를 사용하는 작은 실행기가 URL 하나를 JSON으로 전달한다. Python `webbrowser`, GitHub CLI, `xdg-open`을 사용하는 도구가 이 경로를 사용할 수 있다. `about:blank`는 정확히 이 문자열만 빈 탭 동작으로 수락하며 다른 `about:` 주소·쿼리·프래그먼트는 허용하지 않는다. 도구마다 브라우저 실행 방식을 직접 구현하기도 하므로 모든 CLI 버전의 자동 연동을 보장하지 않는다. 개인 셸 설정에서 기본값을 변경할 수 있다.

앱 업데이트 후 기존 프로젝트를 여는 경우 관리 스크립트가 갱신된다. 이미 실행 중인 셸의 환경변수는 소급 변경되지 않으므로 **새 터미널을 열어야** 기본값을 받는다. 기존 셸을 임의로 종료하거나 실행 중인 명령에 환경변수 설정을 입력하지 않는다.

전송은 기존 앱 내부 Unix 소켓을 사용한다. 수신 시 같은 Android UID, 현재 실행의 토큰, 살아 있는 터미널을 확인한다. 빈 탭 동작을 제외한 HTTP(S) 외 스킴, URL 내 사용자 이름·비밀번호, 제어 문자, 과도한 길이는 거절한다. URL을 셸 명령 문자열로 조합하지 않는다. 전달 실패는 URL·토큰을 포함하지 않는 오류와 0이 아닌 종료 코드로 알린다.

화면이 백그라운드일 때는 자동으로 새 Activity를 띄우지 않는다. 요청은 메모리에서 세션당 하나, 전체 16개, 최대 2분 동안 기다린다. 세션이 끝나거나 시간이 지나면 버린다. 사용자에게 보이는 앱이 요청을 수락한 뒤에만 소비한다.

## HTML 파일 미리보기

`xdg-open /z8/home/simple-html/index.html`은 Python으로 `127.0.0.1`의 빈 포트에 작은 읽기 전용 서버를 만들고 z8 탭으로 연결한다. 같은 터미널에서 같은 폴더의 파일을 다시 열면 서버를 재사용한다. 다른 폴더를 열면 앞 서버를 종료하고 교체한다. 파일을 수정한 뒤 새로고침하면 변경 내용을 읽는다.

서버는 선택한 파일의 정확한 부모 폴더 안에서만 일반 파일을 제공한다. 폴더 목록, 숨김 경로, 상위 폴더 이동, 심볼릭 링크는 제공하지 않는다. 임의 URL 경로를 사용하고 파일·콘텐츠 URL에 대한 WebView 권한은 계속 꺼 둔다. `/assets/...`처럼 서버 루트 기준 경로나 빌드 도구가 필요한 웹 앱은 개발 서버를 실행한 뒤 HTTP 주소로 연다.

예를 들어 프로젝트의 `dist/index.html`이 `/assets/app.js`를 읽는다면 HTML 파일을 누르는 간편 미리보기에서는 해당 자산을 불러오지 못한다. 빌드 결과만 확인하려면 프로젝트 폴더에서 `python3 -m http.server 3000 --bind 127.0.0.1 --directory dist`를 실행하고 브라우저 탭에서 `http://127.0.0.1:3000`을 연다. 개발 중에는 프로젝트가 제공하는 dev/preview 명령을 사용한다. 2026-10-31 호스트 HTTP 재현에서 간편 미리보기의 절대 자산 경로는 404, 일반 루프백 서버의 같은 자산 경로는 200임을 확인했다. 이 결과는 Android WebView 실기기 검증을 대신하지 않는다.

서버는 터미널당 최대 하나이며 30분 동안 사용하지 않거나 시작 후 2시간이 지나면 종료한다. 원래 터미널과 앱 서비스가 살아 있는지 주기적으로 확인하여 종료된 세션의 서버도 정리한다. 미리보기 탭만 닫는 것은 서버 즉시 종료가 아니며, 서버나 앱이 종료된 뒤에는 HTML 파일을 다시 열면 된다.

## 상태와 저장 범위

- 한 번에 하나의 미리보기 WebView만 둔다. 실제 로컬 주소를 열기 전에는 WebView를 만들지 않는다.
- 터미널 탭으로 이동하거나 앱이 백그라운드가 되면 미리보기의 타이머를 일시 정지한다. 프로젝트 전환, 탭 닫기, 화면 소유자 종료 시 WebView를 제거한다.
- 브리지의 인증 URL은 메모리에만 두며 알림 본문·로그·프로젝트 파일·화면 복원 상태에 저장하지 않는다. 이 설명은 **z8의 요청 보관 정책**이다. 기기 브라우저가 관리하는 방문 기록·쿠키·계정 저장 정책까지 변경하지 않는다.
- Custom Tabs는 해당 기기 브라우저의 일반 프로필과 로그인 상태를 사용한다. 브라우저 쿠키는 프로젝트별로 분리되지 않는다. [Custom Tabs의 공유 상태](https://developer.chrome.com/docs/android/custom-tabs)
- 로컬 미리보기 WebView도 현재 앱의 공통 웹 프로필을 사용한다. 쿠키·웹 저장소는 프로젝트별 프로필이 아니며, 같은 웹 출처를 사용하는 다른 프로젝트에서 남은 상태가 보일 수 있다. WebView를 제거하는 동작이 쿠키·웹 저장소를 삭제한다는 의미는 아니다.
- 로컬 미리보기는 프로젝트 간 보안 경계가 아니다. PRoot 자체도 보안 VM이 아니다. 페이지에서 파일·콘텐츠 URL에 접근하는 기능과 임의 JavaScript 네이티브 브리지는 제공하지 않는다.

## 최소 검증 절차

계정 정보 없이 다음을 확인한 뒤 별도로 실제 인증을 검증한다.

```sh
command -v xdg-open
printf '%s\n' "$BROWSER"
xdg-open 'https://example.com/?z8_qa=browser'
xdg-open about:blank
```

외부 URL에서는 기기 브라우저가 열리고 원래 터미널로 돌아오는지 확인한다. `about:blank`는 z8 주소 입력 화면을 열고 Chrome을 시작하지 않아야 한다. `xdg-open file:///etc/passwd`는 브라우저를 열지 않고 거절되어야 한다. 로컬 서버는 터미널에서 `python3 -m http.server 3000 --bind 127.0.0.1`로 시작하고 `xdg-open http://127.0.0.1:3000`으로 앱 안에서 열리는지 확인한다. 검증 후 해당 서버만 종료한다.

브라우저가 없을 때의 안내, 브라우저 종료 후 세션 생존, 화면 접기·펼치기, 프로젝트 전환 뒤 미리보기 제거, 외부 주소로 이동하는 링크의 처리도 확인한다. 실제 로그인 성공은 로그인 화면을 연 결과와 구분해서 기록한다.

## 명령 실행 전 오류와 클립보드 구분

`error building bubblewrap command: cannot establish app-server socket mount isolation`은 Codex가 명령을 시작할 실행 환경을 구성하는 단계의 오류다. 이 경우 `xdg-open` 자체가 실행되지 않으므로 브라우저 브리지의 실패와 구분해야 한다. 이 변경은 Codex sandbox나 승인 설정을 변경하거나 실패한 명령을 자동 재실행하지 않는다.

Codex의 모든 `Failed (exit 1)`이 이 오류를 뜻하지는 않는다. `rg --files`는 조건에 맞는 파일이 없을 때, `printenv NAME`은 변수가 없을 때 1을 반환한다. 앞 명령이 출력에 성공해도 마지막 명령의 종료 코드가 전체 결과에 표시될 수 있다. z8는 이 반환값을 덮어쓰거나 Sites 관리형 컨테이너 환경변수를 위조하지 않는다.

AI에게 로그 복사를 요청하면 CLI가 복사 명령을 실행하려 할 수 있어 같은 실행 환경 오류에 막힐 수 있다. 사용자가 터미널 텍스트를 길게 눌러 선택한 뒤 **복사**, 또는 마우스로 선택한 뒤 **Cmd+C / Ctrl+Shift+C** 하는 경로는 Android 클립보드에 직접 연결되어 CLI 명령 실행에 의존하지 않는다. OSC 52 복사도 터미널에서 지원하지만 앱이 보이는 동안만 처리한다. Linux 데스크톱의 `pbcopy`, `xclip` 설치 여부와는 별개다.
